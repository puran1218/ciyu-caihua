# 词语画猜 PRD

## 1. 产品概述

「词语画猜」是一个面向亲子场景的极简词语画猜小游戏。它的玩法类似「你画我猜」，但产品本身不负责判断对错、不计分、不记录学习成果，只负责在横屏手机上展示一个足够大的词语，作为家庭游戏中的“出题卡”。

这个 app 的核心不是学习打卡，也不是语文测验，而是一个可以在周末、饭后、旅行途中随手拿出来玩的家庭小游戏。词库来源会参考小学语文常见词语，但在前台体验中不强调“年级”“课程”“复习”等学习属性，避免让孩子感到这是一个学习任务。

## 2. 产品定位

一句话定位：

一个给家庭随手玩的语文词语出题卡。

更完整地说：

「词语画猜」是一个横屏手机优先的 PWA 小游戏。家长或猜的人拿着手机，把屏幕朝向画的人。画的人看到屏幕上的词语后，通过画画、动作或提示让其他人猜。每轮结束后，不管猜对还是猜错，都可以直接进入下一个词语。

## 3. 目标用户与使用场景

主要用户是家长和小学阶段的孩子。

典型场景包括：

周末在家亲子游戏；
饭后几分钟随手玩；
旅行、排队、等餐时快速开始一局；
家长希望孩子接触语文词语，但不希望变成正式学习或测验。

核心使用方式：

家长或猜的人拿手机；
手机横屏；
屏幕朝向画的人；
画的人看到词语后开始画或表演；
其他人猜；
一轮结束后点击“下一个”。

## 4. 设计原则

### 4.1 游戏感优先，不强调学习感

虽然词库来自小学语文词语，但首页和主流程不要突出年级、课程、单元、复习、测试等概念。产品应该像一个家庭游戏道具，而不是学习软件。

### 4.2 最大化展示词语

游戏页的核心只有一个词语。词语应该尽可能大、清晰、居中，适合横屏手机远距离观看。两个字要非常大，四个字也要保持强烈视觉存在感。

### 4.3 操作极简

游戏过程中只需要“下一个”和“退出”。不需要答对、答错、计分、排行榜、倒计时、朗读、学习记录。

### 4.4 低启动成本

打开 app 后，用户应该能在 1 次点击内开始玩。首页不应该出现复杂配置。高级设置放在右上角很小的“···”入口里。

### 4.5 词库可扩展

第一版可以先使用占位或示例词库，但代码结构必须为后续真实词库预留。后续词库会单独整理和补充。

## 5. MVP 范围

第一版需要实现以下能力：

PWA 网页应用；
横屏手机优先；
首页显示 app 名、风格选择、开始玩；
首页右上角显示一个很小的“···”设置入口；
游戏页显示一个超大词语；
支持随机下一个词；
支持退出回首页；
支持两种视觉风格：儿童彩色卡片、大字黑白；
默认使用混合词库；
词库结构预留 1–6 年级字段，但首页不直接展示年级选择；
不需要登录；
不需要云端；
不需要学习记录；
不需要统计；
不需要自动朗读；
不需要倒计时；
不需要答对/答错。

## 6. 非目标

第一版明确不做：

学习打卡；
错题本；
答题记录；
家长后台；
AI 判断是否画对；
拍照识别；
语音识别；
自动朗读；
积分、等级、排行榜；
复杂教材版本管理；
按单元选择词语；
用户账号；
多端同步。

## 7. 信息架构

第一版只需要三个主要区域：

首页；
游戏页；
轻量设置面板。

### 7.1 首页

首页只保留最少信息：

App 名称：词语画猜；
风格选择：彩色卡片 / 大字黑白；
主按钮：开始玩；
右上角小入口：···。

首页不要展示大段介绍文案。不要展示“年级选择”“课程词库”“学习复习”等强学习属性内容。

首页氛围应该轻松、干净、可爱，但不要幼稚复杂。

### 7.2 游戏页

游戏页是核心页面。

页面主体：

中央显示当前词语；
词语占据主要视觉空间；
底部或角落显示“下一个”和“退出”；
不要显示解释、拼音、年级、来源、分数或提示。

交互：

点击“下一个”随机切换到下一个词；
点击“退出”返回首页；
同一轮中尽量避免连续重复出现同一个词；
退出后再次开始，可以继续随机。

### 7.3 设置面板

首页右上角“···”打开一个轻量设置面板。

第一版设置建议包括：

词库范围：全部 / 简单 / 普通 / 难一点；
或预留隐藏字段：一年级到六年级，但不在主界面强调。

建议默认展示方式是“简单 / 普通 / 难一点”，背后可以映射到年级或词库难度。这样可以保留控制能力，但不让产品显得像学习软件。

设置面板还可以包含：

是否允许四字词语；
是否只显示两字词语；
重置设置。

如果实现成本要更低，第一版可以只做风格设置和词库范围设置。

## 8. 视觉风格

第一版支持两种风格。

### 8.1 儿童彩色卡片

用于默认体验。

特点：

背景轻松、有颜色；
中央词语像一张大卡片；
按钮温和、圆润；
适合亲子游戏；
不需要过多装饰；
避免太多图标和动画影响词语本身。

### 8.2 大字黑白

用于更极简、更清楚的体验。

特点：

高对比；
白底黑字或黑底白字；
词语极大；
界面接近“词语牌”；
适合光线复杂或距离较远的场景。

## 9. 核心交互流程

### 9.1 首次打开

用户打开 PWA；
看到首页；
默认风格为儿童彩色卡片；
点击“开始玩”；
进入游戏页；
显示随机词语。

### 9.2 游戏中切换词语

当前词语展示在屏幕中央；
一轮结束后，用户点击“下一个”；
系统随机展示另一个词语；
不判断对错；
不记录结果。

### 9.3 退出游戏

用户点击“退出”；
回到首页；
保留上次选择的风格和设置。

### 9.4 修改设置

用户点击首页右上角“···”；
打开轻量设置面板；
调整词库范围或风格相关设置；
关闭设置面板；
点击“开始玩”后使用新的设置。

## 10. 词库需求

词库是这个产品后续最关键的内容资产。第一版实现时需要先预留好结构，但不要求整理完整真实词库。

### 10.1 词库来源

目标词库来自小学语文常见词语，可以包含两字词和四字词。

后续词库整理方向：

一年级到六年级；
每个年级包含通用词语；
不按单元细分；
不强绑定教材版本；
优先选择适合画猜的词语。

### 10.2 词语选择原则

词语应该适合被画出来、演出来或解释出来。

优先选择：

具象名词；
常见动词；
生活场景词；
自然、动物、人物、地点、动作相关词；
容易通过图画表达的四字词语。

谨慎选择：

过于抽象的词；
过于书面化的词；
难以画出来的情绪词；
孩子不容易理解的成语；
需要复杂背景知识才能猜的词。

### 10.3 词库数据结构建议

词库可以用本地 JSON 文件维护，后续方便替换和扩展。

示例结构：

```json
{
  "version": "0.1.0",
  "groups": [
    {
      "id": "grade-1",
      "label": "一年级",
      "difficulty": "easy",
      "words": [
        {
          "text": "太阳",
          "length": 2,
          "tags": ["nature", "drawable"]
        },
        {
          "text": "开开心心",
          "length": 4,
          "tags": ["emotion", "action"]
        }
      ]
    }
  ]
}
```

第一版不需要把 label 直接暴露在首页。可以通过 difficulty 做前台映射：

easy = 简单；
normal = 普通；
hard = 难一点；
all = 全部。

### 10.4 占位词库

第一版可以先提供一批示例词，覆盖 1–6 年级结构即可。真实词库后续单独整理替换。

代码实现上要避免把词语散落在 UI 组件里。词库应该独立放在数据文件或数据模块中。

## 11. PWA 要求

第一版应支持作为网页打开，也应具备基础 PWA 能力。

需要包含：

manifest；
应用名称：词语画猜；
适合横屏使用的显示配置；
基础 icon 占位；
可添加到主屏幕；
尽量支持离线打开；
词库本地加载。

建议 orientation 设置为 landscape 或优先适配 landscape，但也要在竖屏时给出友好提示，例如“横过来更好玩”。

本项目的 PWA 不是部署在站点根目录，而是部署在 Micro.blog 的 `/huacai/` 子路径下。因此，manifest、service worker、词库、图标、CSS 和 JS 的路径都必须按子路径静态托管场景设计，优先使用相对路径。

## 12. Micro.blog 静态托管要求

第一版「词语画猜」采用静态 HTML 托管到 Micro.blog 的方式发布。实现时不要假设存在 Node.js 服务、后端 API、数据库、构建服务器或动态路由。最终交付物必须是可以直接放入 Micro.blog 静态目录的前端文件。

目标访问路径为：

```text
/huacai/
```

也就是说，Micro.blog 发布后，用户应该可以通过以下形式访问：

```text
https://用户的域名/huacai/
```

或：

```text
https://用户名.micro.blog/huacai/
```

### 12.1 文件结构要求

coding agent 需要按照 Micro.blog 静态托管方式组织最终输出目录。

推荐结构：

```text
static/
  huacai/
    index.html
    manifest.webmanifest
    service-worker.js
    app.js
    styles.css
    data/
      words.json
    icons/
      icon-192.png
      icon-512.png
      apple-touch-icon.png
```

如果项目使用 TypeScript、React 或其他构建工具，源码目录可以自由组织，但最终构建产物必须输出为上述静态结构，或者至少保证 `static/huacai/` 下包含可直接发布的完整应用文件。

### 12.2 路径约束

所有资源引用必须使用相对路径，避免使用站点根路径。

应该使用：

```html
<link rel="manifest" href="./manifest.webmanifest">
<link rel="stylesheet" href="./styles.css">
<script src="./app.js"></script>
```

不要使用：

```html
<link rel="manifest" href="/manifest.webmanifest">
<link rel="stylesheet" href="/styles.css">
<script src="/app.js"></script>
```

原因是该 app 会发布在 `/huacai/` 子路径下。如果使用根路径，部署到 Micro.blog 后可能会从博客根目录寻找资源，导致 CSS、JS、manifest、图标或词库加载失败。

### 12.3 Service Worker 作用域

`service-worker.js` 应该放在：

```text
static/huacai/service-worker.js
```

并由 `/huacai/index.html` 注册。

推荐注册方式：

```js
if ("serviceWorker" in navigator) {
  window.addEventListener("load", async () => {
    await navigator.serviceWorker.register("./service-worker.js");
  });
}
```

Service Worker 只需要控制 `/huacai/` 路径下的应用文件，不应该影响 Micro.blog 主站其他页面。

第一版 Service Worker 只需要完成基础离线缓存：

`index.html`；
`styles.css`；
`app.js`；
`manifest.webmanifest`；
`data/words.json`；
必要图标文件。

### 12.4 Manifest 要求

`manifest.webmanifest` 需要适配 `/huacai/` 子路径。

建议配置：

```json
{
  "name": "词语画猜",
  "short_name": "词语画猜",
  "start_url": "./",
  "scope": "./",
  "display": "standalone",
  "orientation": "landscape",
  "background_color": "#ffffff",
  "theme_color": "#ffffff",
  "icons": [
    {
      "src": "./icons/icon-192.png",
      "sizes": "192x192",
      "type": "image/png"
    },
    {
      "src": "./icons/icon-512.png",
      "sizes": "512x512",
      "type": "image/png"
    }
  ]
}
```

注意：

`start_url` 使用 `./`；
`scope` 使用 `./`；
icon 路径使用 `./icons/...`；
不要使用 `/huacai/` 或 `/icons/...` 这类绝对路径，除非最终部署环境已经确认稳定。

### 12.5 词库文件位置

词库文件需要独立放置，便于后续替换。

推荐路径：

```text
static/huacai/data/words.json
```

应用启动时从相对路径加载：

```js
fetch("./data/words.json")
```

不要把最终词库写死在 UI 组件里。第一版可以放示例词库，但必须保留清晰的数据结构，方便后续直接替换 `words.json`。

### 12.6 构建产物要求

如果使用构建工具，最终需要提供一个可发布目录。

建议命令完成后生成：

```text
dist/
  static/
    huacai/
      index.html
      manifest.webmanifest
      service-worker.js
      app.js
      styles.css
      data/
        words.json
      icons/
        icon-192.png
        icon-512.png
        apple-touch-icon.png
```

也可以直接维护 `static/huacai/` 作为源码与发布目录，但要避免引入需要服务器处理的能力。

### 12.7 Micro.blog 发布方式说明

该项目最终会通过 Micro.blog 的静态文件能力发布。实现者需要保证 `static/huacai/index.html` 是一个完全独立页面，而不是依赖博客主题布局的普通文章页面。

不要把 app 实现为 Micro.blog post；
不要依赖博客主题 header、footer 或全局 CSS；
不要让博客主题样式影响游戏界面；
不要使用需要服务器 rewrite 的前端路由；
不要使用 `/huacai/some-route` 这种必须由服务器回退到 `index.html` 的 SPA 路由。

第一版只需要一个入口：

```text
/huacai/
```

所有界面状态，包括首页、游戏页和设置面板，都应该在同一个 `index.html` 应用内部完成。

### 12.8 验收标准补充

Micro.blog 静态托管相关验收标准：

项目包含 `static/huacai/index.html`；
通过 `/huacai/` 子路径打开时，页面能正常显示；
CSS、JS、manifest、icons、words.json 都能从相对路径正常加载；
刷新 `/huacai/` 后页面仍然可用；
添加到手机主屏幕后，app 名称显示为“词语画猜”；
从主屏幕打开后进入游戏首页；
Service Worker 不影响 Micro.blog 主站其他页面；
词库文件可以通过替换 `static/huacai/data/words.json` 更新；
不需要任何后端服务即可运行。


## 13. 响应式与横屏要求

核心体验以横屏手机为主。

游戏页在横屏手机上：

词语必须足够大；
按钮不能遮挡词语；
横向空间要充分利用；
两个字和四个字应有不同字号策略；
安全区域要兼容刘海屏和底部手势区域。

竖屏时：

可以仍然可用；
也可以提示用户横屏；
但不要阻塞使用。

## 14. 状态与本地存储

第一版只需要保存轻量偏好：

当前视觉风格；
词库范围；
是否允许四字词语；
最近一次词语列表位置或已出现词语缓存可以选做。

不保存：

答对答错；
孩子表现；
学习历史；
使用时长；
排行榜数据。

## 15. 随机逻辑

随机词语需要满足：

每次点击“下一个”展示一个词；
尽量避免连续重复；
在当前词库范围内随机；
如果词库数量较少，可以维护一个本轮已出现列表；
当所有词都出现后，再重新洗牌。

推荐实现方式：

进入游戏时，根据设置生成一个候选词数组；
对候选词数组洗牌；
每次点击取下一个；
用完后重新洗牌；
避免新一轮第一个词与上一轮最后一个词相同。

## 16. 可访问性与可用性

词语必须高对比；
按钮点击区域足够大；
不要依赖复杂手势；
字体要清晰；
避免小字号说明文字；
关键操作适合单手点击；
设置入口可以小，但游戏操作按钮不能太小。

## 17. 验收标准

### 17.1 首页

打开 app 后能看到“词语画猜”；
首页只显示名称、风格选择、开始玩和右上角“···”；
首页不出现年级大选项；
点击“开始玩”进入游戏页。

### 17.2 游戏页

游戏页中央显示一个大词语；
词语清晰、醒目、占据主要空间；
点击“下一个”会切换词语；
点击“退出”回到首页；
没有答对/答错按钮；
没有倒计时；
没有分数；
没有学习记录。

### 17.3 设置

点击右上角“···”能打开设置；
设置不影响首页的轻游戏感；
可以选择词库范围或难度；
设置会被本地保存；
重新打开 app 后偏好仍然保留。

### 17.4 风格

支持儿童彩色卡片；
支持大字黑白；
切换风格后游戏页视觉明显变化；
两种风格下词语都足够大、足够清晰。

### 17.5 词库

词库独立维护；
UI 不直接写死词语；
支持后续替换为完整小学语文词库；
当前版本可以使用示例词库；
随机逻辑基于词库数据运行。

## 18. 建议技术实现

第一版建议做成轻量 Web/PWA。

可以使用：

HTML / CSS / TypeScript；
React 或原生 Web 实现均可；
本地 JSON 词库；

## 20. 当前产品判断

当前最重要的产品判断是：不要把「词语画猜」做成学习软件。

词库可以来自小学语文，但体验要像游戏。年级、教材、单元这些概念可以存在于数据结构和隐藏设置中，但不应该成为首页主入口。

首页应该尽可能像一个随手开始的家庭游戏：

看到名字；
选一下风格；
点开始玩；
马上进入大词语卡片。

这就是第一版的核心。
